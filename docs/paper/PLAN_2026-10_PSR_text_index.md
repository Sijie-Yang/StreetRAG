## 1. 定位

**一句话**：把城市里挂在地点上的文本（评论）按 **地点 → 街道 → 区域（PSR）** 三级组织成同一个向量空间里的层次索引，叶子是单条评论/POI，街道和区域是从叶子按需聚合的节点；尺度和划分从分析前提变成可测量的变量（MAUP-aware，不是 MAUP-free）。

**贡献三句话**：
1. **方法**：PSR 层次文本表征与检索索引，聚合方式、区域划分、街道切段都是显式参数，任何划分可从叶子重算。
2. **用途**：LLM agent 用它回答"为什么 / 什么样"的问题时，证据有出处、定位到街道，并能报告结论是否跨尺度一致。
3. **发现**（预注册 H1）：扣掉店铺构成之后，人们对地方的描述差异有多少归于街道、多少归于区域。这是城市科学结果，前两句是工具。

**与 City-RSI 的边界**：City-RSI 研究 agent 自由写代码时空间谓词实现的分叉（F = 跨实现翻转率）；本文研究表征的尺度结构与跨尺度一致性。两篇互引，不比高下，不共用任务集。本文不涉及 PSR 数值 pack、GAC 循环、SpatialMemory。

**与 CityFocus 规则的关系**："不回到上下文注入"针对 CityFocus/City-RSI 的方法选择；StreetRAG 的身份本来就是检索层，RAG 把检索结果放进上下文是其定义，不构成冲突。

## 2. 相关工作与 gap（2026-10-12 核查，详见 `lit_check` 节）

**结论**：没有人用街道段做地点文本的检索单元；没有人系统比较检索单元对 agent 回答和证据定位的影响。沿路网检索已有（无文本、无欧氏对照）。"MAUP 在 RAG 里"的表述未出现。

| 文献 | 单元 | 与本文关系 |
|---|---|---|
| Spatial-RAG, Yu & Mai et al. 2025 (arXiv 2502.18470; TourismQA NYC 评论) | POI 对象 | 最接近的 POI+评论 RAG；TourismQA 可叠 OSM 路网作外部基准 |
| LifePlanner 2026-08 (arXiv 2608.25039; 20 万条 RedNote 帖子) | POI | 最强 place-text agent 基准；发现 agent 失败主因是证据获取不完整 → 本文评估必须把检索层单独测 |

## 4. 方法与可变参数

```
review r  ──embed──▶ e_r
POI p     = pool({e_r : r ∈ p})
street s  = pool({p : p snapped to s})          ← snap_nearest（已有）
region z  = pool({s : s ∈ z})  或  pool({p : p ∈ z})
```

显式参数（每个都是实验变量或敏感性变量）：

| 参数 | 取值 | 角色 |
|---|---|---|
| 聚合方式 pool | (a) 加权均值；(b) LLM 先写街道/区域摘要再 embedding（RAPTOR/GraphRAG 式，有 API 成本）；(c) 多向量：每节点保留 k 个代表向量 | 实验变量（预期 (a) 最差） |
| 街道切段 | OSM 段 / 按路名合并 / 轴线 | 敏感性变量（"可修改线单元"） |
| 区域划分 | 六边形 250/500/1000 m / 行政规划区 / 路网社区（街道图 Louvain） | 敏感性变量（MAUP zoning） |
| 邻域扩展 | 欧氏缓冲 / 沿路网按句法半径 R500/1500/4500 | 实验变量 |
| embedding 模型 | 一个，全程固定 | 固定 |
| LLM（摘要、agent、评判） | 一个，全程固定，不换 | 固定 |

## 5. 预注册假设与判据（待批准后锁定）

统计通用规则：配对置换检验 10,000 次 + Holm 校正（H1、H2 一起）+ bootstrap 95% CI；事后分析一律标 exploratory；不为挽救结果加城市、换指标。

### H1 体验的尺度（城市科学结果）
- 单位：评论 r ⊂ POI p ⊂ 街道 s ⊂ 区域 z（四层嵌套，POI 层必须保留，否则"同一家店"的方差会冒充街道效应）。
- 预处理：e_r 对 POI 类别 one-hot（和评分）回归，取残差；对残差做 PCA，取解释方差达 80% 的前 K 个主成分。
- 模型：每个主成分做四层嵌套方差分量分解（区域 / 街道 | 区域 / POI | 街道 / 评论 | POI），按主成分方差加权平均各层份额。
- 零分布：在区域内随机置换街道标签 1,000 次，得到街道层份额的零分布。
- **判据**：H1（街道主导）成立 ⇔ 街道层份额 > 区域层份额，且置换 p<0.05（Holm），在 ≥80% 的城市上成立。对称地定义 H1′（区域主导）。两者都不成立 → 报告为"扣掉店铺构成后尺度结构不明显"，论文退回方法文章。
- 区域划分三种都要跑，主结论必须在三种划分下方向一致；不一致也是结果（zoning effect），如实报。

### H2 检索层质量（方法结果，无需标注）
- 任务：留出 10% 评论作查询，用索引找回其所属街道与区域。
- 指标：Recall@1/5/10（街道）、Recall@1（区域）。
- 用途：在 dev 切分上选最优聚合方式（这是模型选择，不是假设）；在 test 切分上报告。
- **判据**：选定的 PSR 变体街道 Recall@10 ≥ 平铺 POI 检索再映射到街道的基线 + 0.05，Holm p<0.05。

### H3 agent 证据定位（方法结果，需两名标注者）
- 问题集：60 条，街道 / 片区 / 城市尺度各 20 条，**在建索引前写完并冻结**。
- 条件：(i) 平铺 POI 索引；(ii) PSR 索引；同一 agent、同一提示、同一模型。
- 指标：引用真实率（引的评论存在）、引用定位率（引的评论确实在所答的街道/区域）、跨尺度一致性报告率。两名标注者，记录一致性。
- **判据**：PSR 引用定位率 ≥ 平铺 + 10 个百分点，Holm p<0.05。
- 分层：按 LifePlanner 的教训，先报检索层（H2），再报端到端（H3），避免 agent 探索行为淹没检索差异。

### D1 敏感性（描述性，不作假设）
- 街道切段三种、区域划分三种、邻域扩展两种，报告 H1 份额与 H3 指标的变化幅度。这是论文的 MAUP-aware 承诺。

### 停止规则
- 固定城市清单、固定问题集、固定留出切分，一次性分析，无中期查看，不追加城市。
- 只有基础设施失败（API 报错导致 >10% 调用无效）时暂停，修复后仅重跑失败部分。
- 第二 embedding 模型 / 第二 LLM 只作为预声明的复现扩展，不进主分析。

## 6. 成本（粗估，锁定前按实际定价核对）
- embedding：每城几美元量级（43.8 万条 × ~80 token）。
- LLM 摘要（聚合方式 b）：取决于有评论的街道数，几千到两万条街 × ~1k token 输入；单独报价后由作者批。
- agent 运行：60 问 × 2 条件 × 3 次重复，几美元到几十美元。
- H1、H2、D1 除 embedding 外零 API 成本，全部离线可重放。

## 8. 投稿分档与标题（标题在 H1 出结果后才定）
- 只有方法 + H2/H3 + D1：CEUS / IJGIS / Transactions in GIS。
- H1 或 H1′ 在 ≥80% 城市成立：Nature Cities；子刊还会要 ≥5–10 城、三种划分稳健、一个机制或政策含义（街道尺度管理单元 vs 片区规划单元）。
- 候选标题（按结局）：
  - H1：*Streets, not neighbourhoods, organize urban experience*
  - H1′：*Urban experience is a neighbourhood-scale phenomenon*
  - 都不成立：方法题，如 *A scale-aware index of what people say about cities*
  - 中性：*The scale of urban experience*
